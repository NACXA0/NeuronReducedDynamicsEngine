## 0. 决策摘要

本 RFC 回答两个问题：**代码怎么组织**（八大结构，开发者视角）与**用户怎么理解**（三个产品面，用户视角）。核心结论：

1. **单一仓库，三面呈现**：不拆仓。“果蝇综合模拟”不是独立项目，而是引擎的一个可选后端（FlyGym）+ 一份预制配置 + 一组种子拟合产物。
2. **依赖为单向洋葱**：demo → 引擎/管线 → 核心，且 B（引擎）与 C（管线）互不依赖。“用户用不到的部分”由 pip extras + guarded import 物理隔离。
3. **八大块是内部结构，永不对外**：用户在 README、文档站、import 面上看到的只有三个产品面。
4. **用户金字塔**：A 层（demo）→ B 层（研究引擎，v0.1 主用户）→ C 层（模型管线）。v0.1 交付 A+B 最小闭环 + C 的协议骨架。

## 1. 八大结构（开发者视角）

按**发布耦合度**划分：引擎核心 / 预训练管线 / 具身适配 / 拟合产物 / 文档 / 示例 / 测试 / 基础设施。  
**v0.1 不拆仓**；`nrde[flygym]` 是预留拆仓缝。

对应 RFC-001：核心↔DD-1/2/4/6；管线↔DD-3；具身↔DD-5。

## 2. 依赖：单向洋葱

B 与 C 互不依赖；A 消费 seeds（文件交换 + `config_hash`）；可选依赖一律 guarded import。

| 命令 | 装入 | 产品面 |
|---|---|---|
| `pip install neuron-reduced-dynamics-engine` | 核心+引擎+管线（scipy） | B、C |
| `pip install "neuron-reduced-dynamics-engine[flygym]"` | + FlyGym | A |
| `pip install "neuron-reduced-dynamics-engine[pysr]"` | + PySR/Julia | C 精化 |
| `pip install "neuron-reduced-dynamics-engine[dev]"` | 测试/文档工具 | 贡献者 |

## 3. 三个产品面

| 面 | 入口 | v0.1 |
|---|---|---|
| A 应用 | `nrde demo flygym` / `nrde.make("flygym-demo-v01")` | 接口 Demo（非行为主张） |
| B 引擎 | `nrde run simulate …` | 主力 |
| C 管线 | `nrde offline fit` + `ModelSpec` | 协议骨架 + 示例 04 |

顶层 `__init__.py` 仅导出：`make` / `demo` / `run` / `offline` / `ModelSpec`。

> **实现注记**：源码包目录为 `src/nrde/fitting/`（原 RFC 文稿中的 `offline/`），以免与顶层可调用符号 `nrde.offline` 冲突。CLI 子命令与产品面名称仍为 `offline`。
